주의
- 로컬 T1 토큰은 파일럿이라 측정 못 함 → 로컬 토큰 합계는 39태스크 기준.
- 로컬 토큰은 oMLX 서버 누적 사용량의 전후 차이(다른 사용자가 동시에 쓰면 섞일 수 있음), Sonnet 토큰은 하위 에이전트 기록 합계.
- 오케스트레이터(검토·Red 테스트 배치) 비용은 양쪽이 같아서 비교에서 뺐고, 측정하지 않았다.
- 실전 1회(실제 수집+분류, dry-run): 양쪽 모두 끝까지 실행됨. 두 번 동시에 돌려 Crossref 일시 오류(로컬 쪽) + 모델 분류 비결정성으로 결과가 달랐음. 재현 비교 아님.

## fiftybox-local 개선 후보 (이번 실험에서 나온 것)
- 계약(design.md)에 테스트 실행 명령 한 줄을 넣어야 한다. 없으면 Sonnet 하위 에이전트는 pytest를 못 찾아 테스트를 안 돌리고 제출했다 (T3~T6).
- Red 테스트가 구현 전에 이미 통과하면(T4 settings) 검증이 안 된다. 파일 존재를 단언하는 Red를 쓸 것.
- 계획 문서의 코드 블록 안에 삼중 백틱이 있으면 추출 스크립트가 깨진다.
- 로컬 모델은 코드가 약 2배 길다(주석, 보조 함수). 동작에는 문제 없으나 검토 시 diff가 커진다.
- 구현자의 프롬프트에 "문자열도 허용"처럼 모순되는 말이 있으면 Sonnet은 따르고, 테스트로는 안 잡힌다 (T12). 검토가 필요한 이유.

## 한계
- 검토 비용 미측정. 로컬 T1 토큰 미측정. 캐시 쓰기 TTL 5분 가정.
- 실전 dry-run 비교는 동시 실행과 모델 비결정성 때문에 재현 비교가 아니다.
- 로컬 토큰은 oMLX 서버 전체 사용량 차이라 다른 사용자가 쓰면 섞일 수 있다.
